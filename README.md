# 名古屋路线生成器

适合手机和长辈使用的“景点 / 餐厅选择器 + 路线生成器”。当前包含34个真实景点、8家早餐、18条去重正餐记录，以及正式参考路线、餐厅插入、交通段、预算和地图入口。

发布标记：`v1.0-trip-ready`

出发前验收日期：`2026-08-28`

> 景点、早餐、午餐与晚餐均已进入正式候选；高频交通连接已正式化。资料最后集中复核于2026-08-28。未覆盖转场会标为估算，临时变更与实际车次仍须在当天查看官方入口。

## 本地打开

页面通过 `fetch()` 读取 JSON，因此不要直接双击 `index.html`。在项目目录运行：

```powershell
npm run serve
```

然后打开 `http://localhost:8000/`。

数据结构检查：

```powershell
npm test
npm run test:route
npm run test:route:4b
npm run test:all
npm run test:links:frontend
```

## 当前功能

- 34个景点按区域 / 推荐与类型标签筛选；
- 景点卡显示票价、开放与休馆、三档游览时间、名古屋站出发交通、炎热天气和无障碍提醒；
- 已验证官网、高德地图和Google Maps入口；
- 8家正式早餐卡显示名古屋站周边位置参考、人均、供应时段、排队提示、代表菜及可用官方链接；
- 12家正式午餐和13家正式晚餐按现有区域展示料理类别、附近核心景点、分餐别预算/时段/排队/预约、代表菜和价格类型；
- 早餐、午餐、晚餐读取同一份餐厅数据；7家午晚餐共用同一记录和“想吃”状态，不渲染重复卡片；
- 景点“想去”和餐厅“想吃”；
- 已选清单、取消、清空、复制；
- 选择与字号使用 `localStorage` 保存；
- 任意有效路线日期、时长、体力、起点和上午/下午开始配置；
- 离境日为用户可选设置；未填写希望最晚结束时间时只显示保守提醒，不猜测航班或机场时间；
- 根据休馆、区域分布、建议停留、正式交通和父母休息缓冲，生成可执行的访问顺序与时间线；
- 景点过多或区域分散时主动给出建议子集和留待其他时间的地点；
- 用户“想吃”餐厅真正参与规划；同一餐别只排一家，关闭、跨区或赶不上Last Order时说明原因并保留收藏；
- 大半天/全天可插入附近系统午餐，交通、门票和正式餐费分别汇总，未知费用不按0计算；
- 每段提供Google Maps现场导航、运营方时刻表和高德地点预览；没有正式edge时明确标成估算。

## 第四阶段B路线规则

- 半天目标约3～4小时，大半天约5～6小时，全天约7～9小时；前台只显示取整后的时间范围。
- 少走路和普通模式都采用建议停留时间；少走路通过减少景点、减少跨区和增加休息缓冲实现，不会把每个景点改成极速打卡。
- 少走路：25分钟基础缓冲＋每个景点20分钟；普通：20＋每个景点15分钟；多逛几个：15＋每个景点10分钟。
- 大半天另预留45分钟、全天预留60分钟用餐时间。
- 4A先筛选当天可用景点并裁剪；4B只在建议子集中比较少量排列，不把所有已选内容硬塞进一天。
- 41条高频交通连接覆盖名古屋站至主要区域、犬山、金城ふ头、名古屋港和常见区域内步行组合；其他组合保留带警告的估算fallback。
- Google Maps用于日本现场导航，官方页面用于实际车次，高德只用于中国境内出发前查看地点。
- 普通日期不会自动成为离境日；只有用户主动勾选后才启用远郊与全天活动的保守限制。

## 数据维护入口

- 调整公开起点、时长、体力和路线选项：编辑 `data/trip-config.json`；
- 调整区域字典与排序：编辑 `data/areas.json`；
- 增加景点：编辑 `data/places.json`；
- 增加餐厅：编辑 `data/restaurants.json`；
- 增加交通：编辑 `data/transport.json`；
- 增加高频正式交通连接：编辑 `data/transit-edges.json`（或维护脚本 `scripts/build-transit-data.mjs`）；
- 增加或验证外部来源：编辑 `data/sources.json`；
- 字段关系和格式：查看 `data/SCHEMA.md`。

## GitHub Pages 发布

项目不需要构建步骤。推荐使用 `main` 分支的仓库根目录发布 GitHub Pages：

1. 将项目推送到 GitHub；
2. 在仓库 **Settings → Pages** 中选择 **Deploy from a branch**；
3. 选择 `main` 和 `/(root)`；
4. 等待固定 HTTPS 地址生成后，检查 JSON、路线与地图按钮。

页面资源和 JSON 均使用相对路径，可在 `https://用户名.github.io/仓库名/` 子路径运行。

`research/` 与 `backups/` 是本地内部资料，已由 `.gitignore` 排除，不进入公开仓库。运行所需内容为 `index.html`、`css/`、`js/`、`data/` 和必要的 `assets/`。

## 安全与发布

项目不需要也不应保存 Cookie、登录 Token、密码、住宿状态、航班或其他个人旅行认证信息。当前尚未 Git 提交、上传 GitHub 或发布 GitHub Pages。
